# ⚙️ Pillar 1: Coding5s Course Architecture & Lifecycle

Welcome to the core implementation layer of **Pillar 1**. This directory houses the foundational infrastructure for creating, structuring, and deploying technical courses using the immutable 5-Stage Learning Lifecycle. 

While `CURRICULUM_GENERATOR.md` contains the step-by-step operational manual for utilizing the spreadsheet backend, this document details the architectural structure of the 5 stages and indexes the initial catalog of pre-built Creator and Student Kits included in this release.

---

## 🔬 Anatomy of the 5-Stage Outputs

Every lesson generated by the Creator Kit compiles into a structured text payload distributed to the student via the Student Kit. To maintain the integrity of Controlled Cognitive Friction, the output payload of every single topic is strictly partitioned into 5 distinct behavioral phases:

## 🟥 Stage 1: Practice (Analogic Syntax Imprinting)

The Output Structure: The system exposes a baseline reference code snippet along with its terminal execution boundaries.

The Behavioral Gate: The AI Mentor is explicitly locked. The student is restricted from prompt interactions. They must manually re-type the code line-by-line into their IDE. This physical friction bypasses the passive "spectator trap" of video tutorials and hardwires muscle memory and syntax structure into the brain before any abstraction occurs.

## 🟨 Stage 2: Debug (Brownfield Triage & Error Isolation)

The Output Structure: The student is handed the same code framework from Stage 1, but deliberately infected with intentional errors (e.g., syntax anomalies, logical inversions, or edge-case boundary failures).

The Behavioral Gate: The specialized Debug Mentor activates. Operating under a strict "No Keyboard" constraint, the mentor is forbidden from providing the fixed code block. Instead, it forces the student to analyze error stacks, use local test structures, and explicitly justify why the bug occurred before patching it.

## 🟩 Stage 3: Complete (Semantic Isolation & Logic Ingestion)

The Output Structure: A functional application skeleton where the internal business logic or core data transformation algorithms have been surgically wiped out, leaving empty placeholder functions (# TODO / pass).

The Behavioral Gate: The student knows the expected inputs and deterministic outputs, but must derive the missing transformation layer. The Socratic Mentor guides them through algorithmic trade-offs using guided inquiry and analogies, preventing the student from outsourcing the raw cognitive load to an unconstrained LLM.

## 🟦 Stage 4: Refactor (Optimization & Quality Hardening)

The Output Structure: The student must take their functional code from Stage 3 and subject it to rigorous production-grade constraints.

The Behavioral Gate: The Reviewer Mentor steps in with a technical audit scorecard. The prompt forces the student to optimize the logic against explicit metrics: reducing time/space complexity, enforcing clean architectural patterns (SOLID/OTP principles), handling defensive edge cases, and ensuring code maintainability.

## 🟪 Stage 5: Extend (System Scaling & Architectural Defense)

The Output Structure: A massive change in project requirements is injected into the lesson (e.g., "Scale this single-user script to handle concurrent file processing" or "Add a decoupled caching layer").

The Behavioral Gate: The Adversarial Architect Mentor challenges the student to scale the system. The student must write the expansion, document their design trade-offs, and defend their architectural decisions against the AI's continuous counter-arguments, mimicking real-world senior engineering reviews.

## 3. Two-Part Syllabus Generators (/created_courses/syllabus_generators)

To ensure that the content within the Creator Kits remains dynamically relevant, we include the raw .md files detailing the multi-stage orchestration prompts used to engineer the course syllabi. Every blueprint is strictly divided into two distinct logical executions:

Part 1: The Curricular Decomposition Payload: Forces an LLM to act as an elite Technical Curriculum Designer, breaking a language stack down into granular, non-overlapping atomic topics mapped to professional competency metrics.

Part 2: The Lesson Content Factory: Feeds the structured topics back into the model to output the raw code snippets, intentional bugs, logic gaps, and scaling vectors required to cleanly populate the columns of the Creator Kit.

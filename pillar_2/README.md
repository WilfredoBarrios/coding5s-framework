# 🐝 Pillar 2: The AI Mentor Swarm (System Prompts)

Welcome to the behavioral core of the Coding5s ecosystem. While Pillar 1 handles the curriculum and the 5-stage progression, **Pillar 2 governs the execution**. 

This directory contains the **Mentor Swarm**: a collection of elite, battle-tested **System Prompts** (or Meta-Prompts). These are not generated by Excel formulas; they are highly mature, manually iterated instruction sets designed to overwrite an LLM's default "helpful assistant" behavior, transforming it into a strict, highly specialized pedagogical gatekeeper.

---

## 🧠 The Nature & Objective of a Mentor Prompt

Out of the box, AIs like ChatGPT or Claude suffer from an urge to provide immediate, complete answers. This creates "Epistemic Debt," where students copy-paste solutions without understanding the underlying logic.

The Mentors in this swarm are engineered to eradicate that debt. Their objective is to enforce **Controlled Cognitive Friction**. They achieve this through a specific anatomical structure embedded in their prompts:

1. **Persona & Tone:** Each mentor has a distinct, theatrical personality (e.g., *El Compa Arquitecto*, *El Guardia Fronterizo*). This makes the friction engaging rather than frustrating.
2. **Dynamic Intelligence:** They automatically detect the student's spoken language, cultural slang, programming language, and technical level, adapting their output dynamically without needing manual configuration.
3. **The Gatekeeper Rule (Missing Input Handling):** They refuse to work with passive students. If a student uploads an image or code without a personal explanation, the mentor will **Hard Stop** and demand the student's thought process first.
4. **The "No Keyboard" / Anti-Spooning Rule:** Mentors are strictly forbidden from writing the final, refactored, or solved code for the user. They only analyze, critique, and provide Socratic guidance.
5. **Rigid Output Formatting:** They force the LLM to reply using exact Markdown sections, visual tables, "Scroll Barriers", and even JSON telemetry for diagnostic tracking.

## 🛠️ The Starter Swarm (Included Archetypes)

This directory includes the foundational mentors, ready to be copy-pasted into ChatGPT (as Custom Instructions or System Prompts), Claude, or any local LLM:

### 🏗️ The Legacy Architect (`legacy_architect.md`)
*   **Target:** Reverse Engineering & Brownfield Triage.
*   **Behavior:** A relaxed, street-smart senior developer. It forces junior developers to understand the structural map of code they *didn't* write before attempting to modify it. It isolates code smells, identifies "explosion dangers," and forces a mental test bench before execution.

### 🔄 The Paradigm Bridge (Two-Part Translators)
Transitioning between paradigms (e.g., OOP Python to Functional Elixir) requires breaking old mental models. This is achieved through a unique **2-Part Mentor System**:
*   **Part 1: The Concept Illuminator (`bridge_mentor_s1.md`):** Explains the "why" behind the functional shift. It maps the concepts, provides an empty code skeleton (`#TODO` blocks), and inserts a **Scroll Barrier**, forcing the student to attempt the code before seeing the master solution.
*   **Part 2: The Sparring Partner (`bridge_mentor_s2.md`):** Once the student attempts the translation, this dramatically exasperated (but constructive) auditor steps in. It refuses to give the solution, instead "vandalizing" the student's attempt with inline comments and forcing them to fix their imperative habits.

### 📐 The Abstraction Architect (`math_calculus_architect.md`)
*   **Target:** Mathematics, Calculus, and Geometric Logic.
*   **Behavior:** Combats mechanical memorization in math. If a student uploads a textbook photo, it demands a text explanation. It generates Python (`numpy`/`matplotlib`) or MathStud.io code to create a "Virtual Laboratory," forcing the student to visualize the mathematical reality before touching algebra.

## 🚀 Infinite Extensibility: Build Your Own Mentor

The prompts provided in this directory are fully functional, but their true power lies in their **structural DNA**. By analyzing how these prompts handle constraints, conditionals, and formatting, you can create an infinite swarm of mentors for any discipline.

**Community Expansion Ideas:**
*   **The DevOps Challenger:** A mentor that takes a working `docker-compose.yml` and intentionally asks the student how it would behave if the database container dies.
*   **The UX/UI Interrogator:** A mentor that audits a React component strictly for accessibility (a11y) and state-management efficiency.
*   **The Legal/Contract Auditor:** A non-programming mentor that reads legal drafts, points out logical fallacies or loopholes, and forces the user to rewrite them.
*   **Infinite Language Bridges:** Using the 2-Part Translator logic to build bridges from Java to Rust, JavaScript to Go, or SQL to NoSQL.

### How to Use Them
1. Open the raw `.md` file of the desired mentor.
2. Copy the entire text.
3. Paste it as the initial System Prompt in your LLM platform of choice.
4. Interact with it by providing the required inputs (e.g., Code + Your Explanation).
